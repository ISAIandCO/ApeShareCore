# Операции процессов

## Использование

1. В настройках расширения откройте «Операции процессов». Проверьте профиль на нормализованном событии своего источника: признаки события, PID/GUID **инициатора**, хост и целевой объект. Включите профиль и явно сохраните. Стартовые профили Sysmon, Windows Security и Linux auditd намеренно выключены: названия полей из модели SIEM не гарантируют одинаковое заполнение разными нормализаторами.
2. Откройте/перезагрузите пошаговый граф. Правой кнопкой откройте карточку процесса и нажмите «Загрузить до 25» у нужной категории. Выбор процесса и открытие графа не запускают поиск операций.
3. Кнопка подгрузки читает следующую страницу этой категории. Несколько категорий загружаются независимо. Фиолетовый шестиугольник — категория, зелёный ромб — объект, круг — процесс. Связи parent/child сохраняются.
4. Категорию можно свернуть и раскрыть без повторного запроса. В карточке объекта выберите отдельное событие: доступны исходные поля и открытие события в SIEM.

При добавлении операций не перестраивается процессная модель и не меняются исходный узел, координаты, закрепления, масштаб или смещение. Перезагрузка графа намеренно начинает новый поиск операций. Операции пока не сохраняются в межсессионные снимки графа.

## Категории и источники

| Категория | Стартовые типы Sysmon для Windows | Инициатор в исходной телеметрии | Цель |
|---|---|---|---|
| Файлы | 2, 11, 15, 23, 26 | ProcessId / ProcessGuid | TargetFilename |
| Сеть | 3 | ProcessId / ProcessGuid | DestinationIp, DestinationPort, Protocol |
| DNS | 22 | ProcessId / ProcessGuid | QueryName |
| Реестр | 12, 13, 14 | ProcessId / ProcessGuid | TargetObject |
| Доступ к процессам / памяти | 8, 10 | SourceProcessId / SourceProcessGUID | TargetImage, TargetProcessId |
| Модули | 7 | ProcessId / ProcessGuid | ImageLoaded |

Это поля **исходных событий Sysmon**, а не готовый маппинг KUMA/MP SIEM. Конкретные нормализованные поля задаются профилем. Event 8 означает создание удалённого потока, Event 10 — доступ к процессу; они не относятся к файловым операциям. Sysmon не даёт полного аудита чтения файлов. Нужные типы должны собираться источником.

### Windows Security без Sysmon

| Профиль | События и селектор | Инициатор и объект в исходном событии | Условия |
|---|---|---|---|
| Файлы | 4663, ObjectType=File | EventData.ProcessId → ObjectName; AccessMask | Audit File System и SACL |
| Доступ к реестру | 4663, ObjectType=Key | ProcessId → ObjectName; AccessMask | Audit Registry и SACL |
| Значение реестра | 4657 | ProcessId → ObjectName + ObjectValueName | Audit Registry, SACL Set Value |
| Доступ к процессу | 4663, ObjectType=Process | ProcessId → ObjectName; AccessMask | Audit Kernel Object и SACL; цель должна идентифицироваться |
| Сеть | 5156 / 5157 | EventData.ProcessID → DestAddress:DestPort, Protocol | Audit Filtering Platform Connection; разрешение / блокировка |

4663 означает использование права; 4656 (только запрос дескриптора) не включён. Поле System.Execution.ProcessID не является инициатором операции. Для входящего WFP-трафика DestAddress — локальное назначение, а не удалённый узел. Направление видно в исходном событии; 5157 не выдаётся за успешное соединение. Отдельных надёжных профилей DNS и загрузки DLL по стандартному Security нет.

### Linux auditd

| Профиль | Имена syscall | Требуемая нормализация |
|---|---|---|
| Файлы | open/openat/openat2, creat, unlink/unlinkat, rename/renameat/renameat2, link/linkat, symlink/symlinkat, mkdir/mkdirat, rmdir, truncate, chmod/fchmodat, chown/lchown/fchownat | SYSCALL.pid → путь из PATH/CWD того же audit serial и хоста |
| Сеть | connect | SYSCALL.pid → декодированные адрес/порт SOCKADDR того же события |
| Процессы/память | ptrace, process_vm_readv, process_vm_writev | pid инициатора → декодированный целевой PID: ptrace a1, process_vm_* a0; с учётом ABI |
| Модули ядра | finit_module | pid инициатора → достоверно разрешённый путь по FD; один FD не подходит |

Нужны audit-правила для соответствующих syscall. Поле операции должно содержать декодированное **имя**, а не номер syscall без архитектуры. `ppid`, `uid`, поле `exe` инициатора и отдельная запись PATH не заменяют целевой объект. PTRACE_TRACEME и записи без достоверной цели не подходят. Проверяйте success/exit: событие syscall может описывать неудавшуюся попытку. Для нескольких PATH сохраняются все исходные поля в карточке события, но группировка использует выбранное нормализованное поле цели.

Профиль finit_module применим только если нормализатор разрешает файл по дескриптору. Это не полный аудит загрузки .so: open/mmap не доказывают загрузку библиотеки. DNS через auditd и реестр Windows для Linux не предлагаются. Нужна другая процессно-ориентированная телеметрия для таких запросов. Сырые SYSCALL/PATH/SOCKADDR на клиенте не объединяются по PID.

### Настройка и обновление

В обоих расширениях доступны 15 отдельных профилей. Их условия показаны внутри раскрываемых блоков. Имена полей SIEM и значения источника зависят от установленного пакета нормализации: сверяйте их с фактическим событием. Для ObjectType и syscall универсальное сопоставление не подтверждено; поле оставлено пустым, и включение профиля блокируется, пока оно не задано. Признаки источника, Event ID, классификатор, инициатор, хост и объект участвуют и в запросе, и в разборе результата.

Дополнительно настраиваются действие/AccessMask, результат/success, часть объекта/ObjectValueName и тип PID. Для кастомного строкового PID в MP выберите «Строка decimal / hex»; поддержаны ведущие нули до 16 разрядов. В KUMA стандартные числовые PID распознаются автоматически. Отображаемая операция включает действие и результат, если их поля настроены.

При обновлении сохранённые профили не заменяются, удалённые не возвращаются. Нажмите «Добавить недостающие рекомендуемые профили», чтобы добавить новые шаблоны, сохранив свои сопоставления; повторное нажатие не дублирует их. Добавление и сброс вступают в силу только после «Сохранить профили операций». Профили запуска 4688/Sysmon/execve независимы и не меняются.

## Лимиты и точность

- Одна страница — не больше 25 исходных записей **на сервере**, а не 25 объектов после группировки. Профили одной категории обходятся по очереди, общий бюджет страницы остаётся 25. Пустые и неполные источники проходятся в рамках одного нажатия, следующему источнику передаётся только остаток бюджета; после полной страницы смещение продолжается с числа реально прочитанных записей.
- Сортировка — время, затем уникальный ID; курсор хранит профиль и смещение. Дубли ID не увеличивают число событий объекта. Полная страница означает «возможно продолжение», а не известное общее число. Возможна последняя пустая страница.
- Отдельно отображаются загруженные и не сопоставленные записи. Пустая выборка не означает отсутствие источника. Ошибка API и неподдерживаемая конфигурация — отдельные состояния.
- GUID используется, когда есть и у выбранного процесса, и в профиле операции. Иначе используются PID + точный хост + диапазон графа, начиная не раньше события запуска и заканчивая до следующего известного запуска с тем же PID. PID в hex и decimal нормализуется; GUID сравнивается без скобок и регистра. Несовпадающие GUID не заменяются совпадением PID.
- Неизвестные графу перезапуски процесса, завершения и переиспользования PID исключить нельзя. Это предупреждение показано при PID-сопоставлении. Интервал строится по времени нормализованных событий; задержки доставки также ограничивают точность.
- Offset-пагинация не является снимком базы. Поздно поступившие/удалённые события могут сдвинуть страницы; дубли отбрасываются, для повторной полной выборки следует перезагрузить граф. Не заявляется транзакционная полнота поиска.
- При расширении диапазона графа уже начатая категория сохраняет прежний фиксированный период. Кнопка «Искать в текущем диапазоне» обновляет только эту категорию, сохраняя процессный граф.
- Изменение профилей требует перезагрузки графа; продолжение со старым курсором блокируется. Повторные клики и ответы от устаревшего контекста игнорируются.

## Контракт и хранение

`operations` принимает нормализованные идентификаторы, время и факты. `operation-search` получает профили, функции диалекта, чтения/разбора полей и ограниченного запроса. Здесь нет клиентов SIEM, авторизации или скрытых глобальных зависимостей. `operation-profile-editor` сохраняет только через переданную функцию.

`operationProfiles = {version: 1, profiles: [...]}`. Отсутствие значения создаёт стартовые профили; существующий список и явно пустой список сохраняются. Миграция списка в оболочку версии не меняет значения. Старые настройки создания процессов остаются отдельными.

## Основания и пределы проверки

- [Windows Security 4663](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-4663), [4657](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-4657), [5156](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-5156), [5157](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-5157) — поля инициатора, типа объекта, назначения и условия аудита.
- [Red Hat: Audit](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/9/html/security_hardening/auditing-the-system_security-hardening) — составные события и настройка сбора; [ptrace](https://man7.org/linux/man-pages/man2/ptrace.2.html), [process_vm_readv/writev](https://man7.org/linux/man-pages/man2/process_vm_readv.2.html), [finit_module](https://man7.org/linux/man-pages/man2/init_module.2.html) — смысл аргументов и ограничения.
- [Microsoft Sysmon: события](https://learn.microsoft.com/en-us/windows/security/operating-system-security/sysmon/sysmon-events) — категории и Event ID.
- [Модель событий KUMA 4.6](https://support.kaspersky.ru/kuma/4.6/217941) — типы полей PID, путей, ID и времени; конкретное заполнение зависит от нормализатора.
- [SQL KUMA: ORDER BY, LIMIT, OFFSET](https://support.kaspersky.com/help/KUMA/1.6/en-US/228356.htm) — публичное описание пагинации; реализация использует существующий `KumaAdapter.searchRelated` с POST `/api/v3/events`. Доступное описание SQL относится к старшей по давности версии 1.6; работа запроса на живой 4.6 требует проверки.
- [KUMA 4.6: Auditd](https://support.kaspersky.ru/kuma/4.6/239760) — подключение источника; не доказательство конкретного маппинга syscall.
- [MaxPatrol: Microsoft Sysmon](https://help.ptsecurity.com/en-US/projects/mp10/26.0/help/1031403019) — источник существует. Полную публичную спецификацию маппинга для 27.3 получить не удалось. Используется существующий клиент расширения `/api/events/v2/events`, поля и признаки задаются профилем.

Автотесты проверяют общую модель, адаптеры на синтетических событиях, реальные сериализаторы запросов и DOM-взаимодействия. Это не проверка запросов на установленных SIEM, не проверка фактической телеметрии и не визуальная проверка Firefox.
